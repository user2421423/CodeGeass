# Automated balance dashboard

The dashboard runs **real Knightmare Conquest engine turns** in Node 22, with
the shipped AI controlling every playable faction. It adds *read-only*
observability; it does not adjust units, the map, economy or combat rules.

## Run locally

From the repository root:

    node tools/balance_dashboard.cjs --modes 2017,2018,invasion,division,europe \
      --difficulties normal --runs 1 --max-turns 8 --seed 20261007 \
      --output /tmp/codegeass-balance.json --html /tmp/codegeass-balance.html \
      --summary /tmp/codegeass-balance.md

Open the generated HTML file in your browser. The report is standalone, with
SVG territorial-control graphs, per-faction measurements, and no external
dependencies or network calls.

To compare an experimental build with a baseline report generated by the same
version of the reporting script, supply --baseline /path/to/baseline.json.
The reporter refuses unpaired matrices rather than fabricating a delta.
Matches require the same mode, selected faction, difficulty, and seed.

The available modes are **2017** (World War), **2018** (U.F.N. Conquest),
**invasion** (Invasion of Japan), **division** (Division of Japan) and
**europe** (European War). Use --players britannia,cf to filter selected
perspectives when necessary, and --snapshot-turns 10,20,30 for additional
time-series checkpoints. The --difficulties normal,hard,challenge,elite
option is valid; larger runs are better started from GitHub Actions.

## GitHub Actions

Select **Actions → Automated balance dashboard → Run workflow**.

- **Smoke**: 1 seed per selected faction, 8 turns.
- **Standard**: 3 seeds per selected faction, 30 turns.
- **Deep**: 5 seeds per selected faction, 50 turns.

The workflow also runs a smoke comparison on relevant changes to main, and
a standard comparison weekly. The optional **baseline_ref** accepts a Git ref
or commit SHA. By default, the workflow compares its checked-out commit to its
first parent. It fetches both revisions, runs the *same new reporting scripts*
against their respective shipped game engines, checks source/tests, and uploads
a standalone dashboard along with baseline/candidate JSON and Markdown.

**No baseline game files are modified.** The workflow runs in disposable
Git worktrees and has read-only repository permissions.

## What the figures mean

- **Wins:** the selected faction's victories (2018 Britannia and Euro
  Britannia share a coalition result). A scenario requires total ownership
  of its 44 cities to count as won.
- **Unresolved:** the simulation horizon ended before the game's victory
  condition was achieved. This is *not* a loss.
- **Cities:** average final city ownership. A recaptured
  city is counted each time its owner changes.
- **Own losses:** observed formations that no longer exist. A formation can
  be destroyed without a visually played animation.
- **Naval landings:** carrier deployment or sea-to-land movement events,
  not proof that an invasion seized a city.
- **Front switches:** changes to persistent AI theater assignment records,
  not necessarily completed transfers.
- **Runtime:** useful for performance regressions, but varies between
  machines and is not a direct AI-skill metric.

Paired reports show experimental-minus-baseline deltas. The chosen player
perspective still matters: existing scenarios apply some difficulty bonuses
to its *opponents*. The runner controls the chosen player's army through AI
instead of manual orders; it does not erase those real game setup rules.

### Limits and safeguards

The observer clears normal *human elimination* end screens when multiple
AI powers remain so a regional war can finish. It does not declare the sole
remaining city owner the winner until the scenario's actual victory rule
passes. Conquest coalition and armistice outcomes use the same underlying
city-control conditions as the game. Other movement, combat, production
and turn sequencing continue through the existing engine methods.

Multi-seed results are diagnostics, not human win rates or a guarantee of
balance. Favor separate held-out seeds and inspect territory, casualties,
reassignments, naval activity and performance together. Before merging
gameplay changes, run:

    node tools/build_sources.cjs --check
    node --test tests/*.test.cjs
    node tests/ui-smoke.cjs
    node tools/validate_assets.cjs --tracked
    python3 tools/check_map.py
